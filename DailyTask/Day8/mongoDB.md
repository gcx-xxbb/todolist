## 基础概念

### 数据模型：文档与集合

MongoDB的数据模型是其最显著的特征，主要由以下两部分构成

- 文档：这是MongoDB中数据的基本单元，类似于关系型数据库中的行(Row)。文档采用BSON格式存储，这是一种类似JSON的二进制格式，支持字符串，数字，数组，甚至嵌套的文档对象
  - 无模式：同一个集合中的文档无需拥有相同结构。可以随时为某个文档添加新字段，而不会影响集合中的其他文档。这为快速迭代的应用开发提供了极大的灵活性
  - 唯一标识符：每个文档都有一个`_id`字段，作为其唯一的标识符。
- 集合：一组文档的集合，类似于关系型数据库中的表(Table)。一个数据库可以包含多个集合。

### 概念对比：SQL vs MongoDB

| SQL 概念           | MongoDB 概念      | 说明                                                   |
| :----------------- | :---------------- | :----------------------------------------------------- |
| 表 (Table)         | 集合 (Collection) | 集合中的文档结构可以不同，而表的行结构必须相同。       |
| 行 (Row)           | 文档 (Document)   | MongoDB 的基本数据单元，是一个 BSON 对象。             |
| 列 (Column)        | 字段 (Field)      | 文档中的键值对，值可以是任意类型，包括其他文档或数组。 |
| 主键 (Primary Key) | `_id`             | 每个文档都拥有一个唯一的 `_id` 字段。                  |

### 架构组件

在生产环境中，MongoDB通常以集群方式部署，以实现高可用性和海量数据处理能力。

- 副本集：一组维护相同数据集的MongoDB实例。它通过数据冗余和故障自动转移来保证高可用性。当主节点发生故障时，副本集中的从节点会选举出新的主节点，确保服务不会中断
- 分片集群：用于处理超大规模数据集。它通过分片技术将数据水平拆分，并分布到多台服务器上。
  - 分片：实际存储数据的节点，每个分片本身可以是一个副本集。
  - 路由：一个无状态的路由器，负责将应用程序的请求路由到正确的分片上。
  - 配置服务器：存储集群的元数据和配置信息，是整个分片集群的大脑。

### 主要特性与优势

- 高性能：得益于高效的存储引擎(如WiredTiger)、内存映射以及强大的索引支持(包括文本索引、复合索引、地理空间索引等)，MongoDB在处理高并发读写和海量数据时表现出色。
- 高可用性：通过副本集机制，MongoDB原生支持数据冗余和自动故障恢复，确保服务持续可用。
- 水平扩展性：分片是MongoDB的内置能力，可以轻松的将数据分布到多个服务器上，实现近乎线性的性能提升，突破单台服务器的性能瓶颈。
- 灵活的文档模型：文档结构与应用程序中的对象模型高度契合，减少了对象关系映射的复杂性。嵌套文档和数组的使用可以避免复杂的多表连接操作，提升数据访问效率。
- 丰富的查询语言：支持强大的查询和聚合框架，可以进行范围查询、模糊查询、全文搜索以及复杂的数据分析和统计。
- 事务支持：从4.0版本开始，MongoDB支持多文档ACID事务，满足了金融交易等对数据一致性有较高要求的场景。

### 适用与不适用场景

#### 适用场景

MongoDB特别适合以下业务场景：

- 内容管理系统(CMS):灵活存储文章、评论、标签等非结构化数据。
- 实时分析：处理高并发写入的用户行为日志、点击流数据。
- 物联网(IOT)：存储海量设备传感器上传的数据。
- 游戏应用：存储玩家信息、装备、技能等复杂数据结构，并支持高并发访问。
- 社交网络：存储用户动态、好友关系、并利用地理空间索引实现“附近的人”等功能

#### 不适用场景

尽管功能强大，但MongoDB在某些场景下并非最佳选择：

- 高并发强事务场景：虽然支持事务，但在处理高频，高冲突的复杂事务(如核心银行系统)时，其性能和成熟度相比传统关系型数据库仍有差距。
- 复杂多表关联查询：对于需要频繁进行多层级、复杂连接(JOIN)的报表分析或数据仓库场景，关系型数据库的表达能力和性能更优。

## Mongoose操作

1. 链接数据库：mongoose.connect('mongodb://localhost:27017/bookStore'); bookStore是数据库的名字
2. 创建schame:const bookSchema = new mongoose.Schema({title:String});类似这种 强行控制数据格式为事先约定好的 防止出错
3. 创建model:const Book = mongoose.model('Book', bookSchema);model 我的理解就是找到这个数据库的一个集合，没有就创建
4. 对数据进行增删改查操作
   - 增加数据：const book = new Book({title:'《Node.js开发实战》'}) book.save()
   - 删除数据：Book.deleteOne({title:'《Node.js开发实战》'})
   - 修改数据：Book.updateOne({title:'《Node.js开发实战》'},{$set:{title:'《Node.js开发实战》'}})
   - 查询数据：Book.find({title:'《Node.js开发实战》'})
