3.1 请简述Express中间件的执行顺序为什么重要，并举例说明。
中间件按照注册顺序依次执行 所以一定要按照想要执行的顺序来注册 并且中间件的注册要在路由之前 比如说 内置中间件express.json() 如果在解析req.body之后再注册express.json() 会导致express.json()无法解析req.body 只能得到undefined

3.2 什么是路由模块化？它有什么好处？
就是如果所有的路由都放到app.js这个主文件中 那么会很混乱 后续要修改逻辑也会很麻烦
所以需要将不同的路由按照他们的功能进行分类 创建一个routes文件夹 这样不同的模块可以由不同的人员维护
不同的路由模块之间是不同的 因此不需要担心逻辑冲突
后续只要在app.js中引入routes文件夹下的所有路由模块 就可以完成路由的配置
也可以为某个路由模块单独创建路径和中间件 比如说`app.use('/users',checkAuth,usersRouter)`
这样做的话 同一前缀下的路径都会经过checkAuth中间件的校验了

```js
const validateUser = (req, res, next) => {
  const { username, email, password } = req.body;

  // 1. 检查用户名（非空，3-20个字符）
  if (!username || username.length < 3 || username.length > 20) {
    return res.status(400).json({ error: '用户名必须为3-20个字符' });
  }

  // 2. 检查邮箱格式（使用正则表达式）
  const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  if (!emailRegex.test(email)) {
    return res.status(400).json({ error: '邮箱格式不正确' });
  }

  // 3. 检查密码（至少6位）
  if (password.length < 6>) {
    return res.status(400).json({ error: '密码至少需要6位' });
  }

  // 4. 验证通过，继续处理
  next();
};

// 使用示例
app.post('/register', validateUser, (req, res) => {
  // 注册逻辑
  res.json({ message: '注册成功' });
});
```
