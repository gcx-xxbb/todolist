## 核心概念

在Express在框架中 中间件是一个核心概念 它本质是在一系列客户端请求和服务端最终响应之间执行的函数
可以把它想象成一个处理请求的流水线 每个中间件都是流水线上的一个工位 对请求进行特定的处理

### 中间件的构成

一个中间件可以访问三个关键对象

1. req(请求对象):代表客户端发来的HTTP请求
2. res(响应对象):代表服务端向客户端发送的响应
3. next(下一个中间件函数):一个函数，用于将控制权传递给下一个中间件

### 中间件能做什么

在请求-响应的循环中，中间件函数可以执行以下任务:

- 执行任何代码:例如记录任何日志，打印时间戳等
- 修改请求和响应对象:例如在req对象上添加自定义属性,或在res对象上设置响应头
- 结束请求-响应周期:直接发送响应给客户端，例如在身份验证失败时发送401状态码给客户端
- 调用堆栈中的下一个中间件:通过调用next()函数，将控制权交给下一个中间件继续处理

### next()的作用

next()是控制中间件流水线如何运作的关键

- 调用next():表示当前中间件的任务已经处理完成，请求可以继续传递给下一个中间件或路由
- 不调用next():如果中间件没有结束请求-响应周期(例如没有调用res.send()),也没有调用next(),那么请求将会被挂起，客户端永远收不到响应
- 调用next(err):如果中间件内部发生错误，可以调用next(err),Express会跳过后续所有普通中间件，直接跳到错误处理中间件

## 中间件的分类

| 分类           | 描述                                                     | 代码特征                |
| :------------- | :------------------------------------------------------- | :---------------------- |
| 应用级中间件   | 绑定到整个 `app` 实例，影响所有或大部分请求。            | `app.use(...)`          |
| 路由级中间件   | 绑定到 `express.Router()` 实例，作用域更小，用于模块化。 | `router.use(...)`       |
| 内置中间件     | Express 自带的工具，如解析 JSON、托管静态文件。          | `express.json()`        |
| 第三方中间件   | 社区开发的强大工具，如日志记录 `morgan`、安全 `helmet`。 | `require('...')`        |
| 错误处理中间件 | 专门用于捕获和处理应用中的错误，有 4 个参数。            | `(err, req, res, next)` |

## 中间件的使用方法

- 应用级中间件:通过app.use()绑定到整个应用，会对所有进入的请求生效
- 路由级中间件:可以将中间件作为参数，直接应用在某个或某几个特定的路由上，实现更精细的控制。在身份验证，权限检查这方面比较常见
- 错误处理中间件:特殊的中间件 有(err, req, res, next)四个参数。必须定义在所有路由和中间件之后，用于集中捕获和处理应用中的错误
- 常用第三方中间件
  - morgan: 用于记录请求日志
  - cors:解决前后端分离的跨域问题
- 注意事项:
  - 执行顺序至关重要:中间件按照他们被定义的顺序依次执行。例如 解析请求体的express.json()必须在需要使用req.body之前定义
  - 别忘了调用next():如果中间件没有结束响应(如res.send())就必须调用next(),否则请求会一直处于挂载状态
  - 错误处理:在中间件发生错误时，应调用next(err),Express会自动跳转到错误处理中间件

## 路由级中间件


指绑定在express.Router()实例上的中间件，而不是绑定在主app上

- 可以想象成特定区域的保安
  应用级中间件是小区门口的保安 所有请求都要被检查
  路由级中间件是小区某个房间的保安 只对这个房间的请求进行检查
-模块化
模块化就是将单独的功能抽离出来封装成模块 单一职责就单一模块 比如所有用户的操作就可以放到一个user.js模块中
