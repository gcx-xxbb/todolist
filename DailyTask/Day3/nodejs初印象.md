## NodeJs是什么

nodejs是一个基于v8引擎的js代码运行环境

## 核心特点

1. 单线程事件循环
   - Node.js使用单线程的事件循环模型
   - 通过事件驱动和回调函数处理并发请求
   - 避免了传统多线程编程中的线程切换开销
2. 非阻塞I/O
   - 所有的I/O操作(文件读写、网络请求、数据库操作等)都是异步的
   - 当等待I/O操作完成时，程序不会被阻塞，可以继续处理其他任务
   - 大大提高了应用程序的吞吐量
3. 跨平台
   - 支持windows,linux,macOS等多种操作系统
   - 一次编写，到处运行
4. 丰富的生态系统
   - npm有数百万个开源包
   - 活跃的开发者社区

## 与浏览器javascript的区别

- 编写的JavaScript会通过v8引擎 再通过nodejs的Bindings，将任务放到Libuv的事件循环中
- libuv是使用c语言编写的库
- libuv提供了事件循环、文件系统读写、网络I/O、线程池等等内容
- 和浏览器JavaScript相比 少了将html/css文件通过blink引擎进行渲染工作

## Node.js是单线程的 为什么可以处理高并发请求

我的理解是 Node.js虽然是单线程的 但是它的事件循环是异步的 也就是说 当任务执行过程中 并不会阻塞线程 线程会继续执行下一个任务 因此可以处理高并发请求

## require('fs') 和 import fs from 'fs' 有什么区别？

这俩对应的分别是 CommonJS 和 ES Module
CommonJs我的理解是动态导入 可以在代码的任何地方导入 但是ES Module 是静态导入 只能在模块的顶层导入

## \_\_dirname 和 process.cwd() 有什么不同？

- \_\_dirname：当前文件所在的目录 对应当前文件所在的物理位置 不会被更改 CommonJs原生支持 路径层级固定为文件所在目录
- process.cwd()：进程启动的工作目录 取决于执行代码的位置 可以通过process.chdir()方法修改 支持所有环境 路径层级可能比文件目录层级更高

## Node.js 适合开发什么类型的应用？不适合什么类型？

1. 适用场景
   - Web应用
     - RESTful API
     - 单页面应用的后端服务
     - 实时Web应用
   - 实时应用
     - 聊天应用
     - 在线游戏
     - 协作工具(如在线文档编辑)
   - 微服务架构
     - 轻量级微服务
     - API网关
     - 服务间通信
   - 工具和命令行应用
     - 构建工具(webpack,gulp)
     - 脚手架工具
     - 自动化脚本
   - 物联网应用
     - 设备数据收集
     - 传感器数据处理
2. 不适用场景
   - Cpu密集型任务
     - 图像/视频处理
     - 复杂的数学计算
     - 大数据分析
   - 需要大量计算的应用
     - 机器学习训练
     - 科学计算
     - 加密货币挖矿
