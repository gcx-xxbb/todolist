## CommonJS和ES Module

1. 引入方式
   - CommonJs是动态导入 可以在代码的任何地方导入
   - EsModule是静态导入 在编译阶段进行导入 不能动态加载语句 所以import不能写在块级作用域和判断条件内
2. 使用语法
   - commonjs:

   ```js
   //a.js
   const obj = { name: 'hello' };
   module.exports = obj;
   //b.js
   const obj = require('./a.js');
   console.log(obj.name);
   ```

   - esModule:

   ```js
   //a.js
   export const title = 'esmodule';
   export const message = 'hello esmodule';
   const obj = { name: 'hello' };
   export default obj;
   //b.js
   import obj, { title, message } from './a.js';
   console.log(title, message, obj.name);
   ```

3. 加载运行
   - commonjs: commonjs在代码运行时加载 因为它导出的是整个对象 需要在脚本运行完成后才能生成
   - esModule: esModule输出的不是一个对象 它是在静态分析编译时输出接口 它的对外接口只是一种静态定义 可以理解为生成一个个引用变量 在模块读取的时候再去取
4. 加载模式
   - commonjs: commonjs是同步加载 在服务器端大多读取本地资源模块 速度非常快
   - esModule: esModule是异步加载 在浏览器端会请求加载网络资源模块 使用同步加载会出现卡顿的情况

## 模块加载机制
在Node中 每个文件都被视为一个模块 当使用require语句导入模块时 Node.js会按照一定规则进行模块的查找和加载
加载机制大致可以分为以下几个步骤：
1. 路径解析：根据模块的路径进行查找 可以是绝对路径和相对路径
2. 文件定位：根据路径解析结果定位到文件 可以是.js,.json,.node等
3. 编译执行：将模块的代码进行编译和执行，生成对应的模块对象
4. 模块缓存：将模块对象缓存起来，避免重复的加载和执行
